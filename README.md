# AURA: сайт студії йоги із серверною частиною

Node.js + Express + SQLite. Форма запису надсилається на сервер через Fetch API, повідомлення зберігаються в базі даних, переглядати й видаляти їх може лише адміністратор.

## Вимоги

- Node.js 20 або новіший (https://nodejs.org, версія LTS)

## Запуск

1. Відкрийте термінал у папці проєкту.
2. Встановіть залежності:

       npm install express better-sqlite3 dotenv

3. Створіть файл `.env`: скопіюйте `.env.example` і задайте свій пароль адміністратора:

       PORT=3000
       ADMIN_USER=admin
       ADMIN_PASSWORD=

4. Запустіть сервер:

       npm start

5. Відкрийте в браузері:
   - сайт: http://localhost:3000
   - повідомлення (потрібен вхід): http://localhost:3000/admin.html

Базу даних створює сервер сам під час першого запуску: файл `data/messages.db` за схемою з `schema.sql`.

## Структура

    server.js        сервер, REST API, автентифікація
    db.js            робота з базою (параметризовані запити)
    schema.sql       структура таблиці messages
    .env.example     приклад налаштувань (реальний .env не додавати до архіву)
    public/          сайт: index.html, styles.css, script.js, images/
    public/admin.*   сторінка адміністратора

## Таблиця messages

| Поле | Тип | Опис |
|---|---|---|
| id | INTEGER, PRIMARY KEY AUTOINCREMENT | ідентифікатор |
| name | TEXT NOT NULL | ім'я |
| email | TEXT NOT NULL | електронна адреса |
| message | TEXT NOT NULL DEFAULT '' | текст повідомлення |
| created_at | TEXT NOT NULL DEFAULT (datetime('now')) | дата створення (UTC) |

## REST API

| Метод і адреса | Доступ | Дія |
|---|---|---|
| POST /api/messages | усі | зберегти повідомлення з форми (JSON) |
| GET /api/messages | адміністратор | список повідомлень |
| DELETE /api/messages/:id | адміністратор | видалити повідомлення |
| POST /api/login | усі | вхід (логін і пароль з `.env`) |
| POST /api/logout | усі | вихід |
| GET /api/session | усі | чи виконано вхід |

## Безпека

- Усі SQL-запити параметризовані (`?`), дані користувача не вставляються в текст запиту.
- Дані перевіряються на сервері: ім'я 2–50 символів, коректний email, повідомлення до 500 символів.
- Перегляд і видалення доступні лише після входу. Сесія зберігається в cookie `HttpOnly` із `SameSite=Strict`, після 5 невдалих спроб входу з однієї адреси вхід блокується на 15 хвилин.
- Пароль і налаштування лежать у `.env`, який виключено з архіву й з Git (`.gitignore`).

## Перевірка збереження після перезапуску

1. Надішліть форму на сайті.
2. Зупиніть сервер (Ctrl+C) і запустіть знову (`npm start`).
3. Відкрийте `/admin.html`, увійдіть: повідомлення на місці.
